# SIG 运营看板：存量界面优化提示词

## 目标

在现有 `SIG运营看板-平台风格设计稿-v1.html` 的业务交互上优化首屏理解与任务导航，让首次进入的 SIG 成员和运营角色能迅速知道“我能做什么、从哪里开始、如何跟进”。以 `SIG运营看板诉求方提供的草图.html` 的五步业务路径作为需求来源，保留低保真已经形成的四页能力结构。

## 设计系统（可替换槽位）

当前采用**输入稿自带的 opencann-frontend / DevUI 视觉基线**：蓝色品牌色、HarmonyOS Sans SC 字体、玻璃卡片、页签和表格样式。沿用已有 CSS token 和组件，不另建配色、字体、按钮体系。优化应作为单文件 HTML 内联 CSS/JS 增量实现。

## 角色与场景

SIG Maintainer/Committer：本 SIG 资源申请、跟进和成果查看。运营管理员：跨 SIG 总览、代提申请与查看自己提交的申请。运营审核员、营销审核员、运营操作员：在申请与审批/资源配置中处理各自任务。严格沿用原型 `canSeeView` 权限函数；无权限动作不显示。

## §C 问题到可验收目标

1. 总览新增“从发起推广到复盘成果”任务区，主按钮进入资源申请，次按钮进入申请与审批。按钮权限随角色变化，不产生无权限死路。
2. 五步路径保留：了解 SIG 运营、SIG 上线、仓库开源、运营资源申请、计划与目标。上线与仓开源进入同一个资源申请页，计划与目标定位到总览中的目标区。
3. 申请首步继续展示审批阶段链；超过一段的职责说明默认折叠，点开能完整阅读。基础信息前给一句操作提示。
4. 角色提示区区分运营管理员与本 SIG 成员，明确跨 SIG 或本 SIG 的作用范围。所有示例数字均标为演示数据。
5. 新增卡片和按钮可键盘聚焦，焦点清晰可见；窄屏时新卡片自动换列，不产生横向溢出。

## §D 跨视图一致性约束

- 保留四页页签顺序：运营总览、资源申请、申请与审批、资源配置。
- 保留现有审批状态、排期、资源配置和目标数据结构；不改电子流逻辑。
- 文案统一使用“SIG”“资源申请”“申请与审批”“运营总览”。
- 新增页面入口复用原 `switchView`；角色判断复用 `canSeeView`。

## §E 各视图要求

### 运营总览

任务入口置于 SIG 选择与报表上方。用一条简洁流程说明“申请 → 审批 → 执行反馈 → 复盘”。五步路径是业务地图，不是五套业务表单。

### 资源申请

首步保持基本信息优先、后续资源和素材的三步向导。长说明通过原生 `details` 折叠。必填、字符数和错误反馈沿用当前逻辑。

### 申请与审批

沿用“我提交的／待我处理／我已处理”结构、列表筛选、审批链；从总览提供直达入口。

### 资源配置

不改宣传方式 × 媒体的行级配置和审批规则。

## §F 状态覆盖

- 无权限：动作隐藏，沿用已有无权限页。
- 暂无申请或目标：保留原型空态；真实接入时增加明确下一步操作。
- 已驳回、审核中、已通过：继续使用原状态机，不将“已通过”误表示为全流程结束。
- 加载与接口错误：当前是静态原型，没有真实接口；工程阶段依接口契约补齐，不以假数据冒充真实状态。

## 输出

交付 `optimized-demo/index.html`：单文件、CSS 和 JS 内联、可双击查看。首次打开默认运营总览；角色切换、资源申请和申请与审批仍可使用。保留源文件原有业务示例与交互功能。
